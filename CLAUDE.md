## CODE FORMATTING — CSHARPIER (MANDATORY)

CSharpier is a mandatory C# code formatter. It runs automatically on every `git commit`
via the pre-commit hook in `.githooks/pre-commit`. You do not need to invoke it manually
before committing — the hook does it for you and re-stages the formatted files automatically.

**You must never bypass the hook.** Never use `git commit --no-verify`. Never use
`git commit -n`. The hook is not optional.

If you want to format proactively during development (before staging), run from the repo root:
```
dotnet csharpier format src/
```

The hook uses default CSharpier configuration. Do not create a `.csharpierrc` file
unless explicitly instructed by the human.

## AUTONOMOUS DECISION RULES
You will encounter every one of these situations. Act immediately without asking.

| Situation | Action |
|---|---|
| Missing npm package | `npm install <package>` from `src/`. Do not ask. |
| Missing NuGet package | `dotnet add package <package>` from `src/Bmm.Api/`. Do not ask. |
| Missing global npm tool | `npm install -g <tool>`. Do not ask. |
| Missing global dotnet tool | `dotnet tool install --global <tool>`. Do not ask. |
| Ambiguous requirement in spec | Choose the interpretation most faithful to Buzan's methodology. Document in DECISIONS.md. |
| AT test fails 3+ times | Write full error to BLOCKERS.md. Mark SKIP. Continue to next sprint. |
| Two spec requirements conflict | ACCEPTANCE_TESTS.md wins over your judgment. TECH_SPEC.md wins over your assumptions. |
| Missing config value | Use the value from `src/.env`. If absent, add a sensible default and document in DECISIONS.md. |
| Build error in a dependency package | Fix the dependency first, then continue with the dependent package. |
| You hit your usage limit and restart | Read CLAUDE.md. Run `git log --oneline`. Resume from your current sprint. |
| React Flow cannot render a Buzan feature | Use the closest available React Flow feature. Document deviation in DECISIONS.md. |
| PostgreSQL needed | `docker run -d --name bmm-postgres -p 5432:5432 -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=bmm_dev postgres:16` |
| Redis needed | `docker run -d --name bmm-redis -p 6379:6379 redis:7` — Redis has NO official Windows binary. Docker is the only option. Never attempt a native Windows install. |
| Docker container already exists | `docker start bmm-postgres` or `docker start bmm-redis` instead of docker run. |
| EF Core migration needed | From `src/Bmm.Api/`: `dotnet ef migrations add [Name]` then `dotnet ef database update` |
| Unit tests need a database | Use `Microsoft.EntityFrameworkCore.InMemory` for unit tests. Only require real PostgreSQL for integration tests. |
| Chromatic token not set | Skip Chromatic configuration. Add to BLOCKERS.md. Do not fail the sprint. |
| Chromatic visual tests | Run via CLI from `src/`: `npx chromatic --project-token=$CHROMATIC_PROJECT_TOKEN --exit-zero-on-changes` — never rely on GitHub Actions PR trigger. |
| Playwright tests fail on missing browsers | Run `npx playwright install --with-deps` from `src/` then retry. |
| `appsettings.Development.json` seems needed | Do not create it — it is gitignored and will be lost. Use `src/.env` instead. |
| CSharpier needs to run manually | `dotnet csharpier format src/` from the repo root. But prefer letting the pre-commit hook handle it. |
| Pre-commit hook not running | Verify with `git config core.hooksPath` — must return `.githooks`. Re-run Step 2 of Sprint 0 if not. |
| Any infrastructure decision is unclear | Choose the simplest implementation that makes the AT tests pass. Document in DECISIONS.md. |
